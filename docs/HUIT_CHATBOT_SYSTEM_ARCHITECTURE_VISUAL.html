🎨 Vòng Đời Artifact & Sinh Ảnh (Ultralight Flow)

Minh họa hai luồng tách bạch: Kế hoạch biểu đồ/tài liệu và xử lý tạo ảnh có khử trùng lặp (Deduplication).

📄 1. Luồng Vòng Đời Artifact (Excel, Word, PDF)
  1. Phát hiện ý định: Nhận diện yêu cầu học phí/điểm chuẩn qua artifact_intent.py.
  2. Ultralight Plan: POST /api/artifacts/plan tạo manifest JSON nhẹ < 32KB.
  3. Xem trước tức thì: GET /api/artifacts/{id}/preview trả về vector SVG < 4KB trong < 15ms.
  4. Yêu cầu xuất file nặng: POST /api/artifacts/{id}/export trả về HTTP 202 Job Accepted.
  5. Background Worker: Nhận job từ MongoDB Lease Queue, gọi Engine OpenPyXL/Docx/PDF.
  6. Lưu trữ an toàn: File nhị phân chuyển vào StorageAdapter; MongoDB lưu metadata.
  7. Tải file bảo vệ: Trình duyệt nhận Signed URL có HMAC hash tải an toàn.
🖼️ 2. Luồng Sinh Ảnh & Upscale Có Deduplication
  1. Yêu cầu tạo ảnh: Kiểm tra contract schema huit.api.image-create-request.
  2. Băm Canonical Hash: Tính SHA-256 từ (prompt, style, model, dimensions).
  3. Khóa chống trùng: Khóa asyncio.Lock theo hash ngăn chặn 2 user sinh cùng lúc.
  4. Kiểm tra bộ đệm: Nếu hash đã tồn tại trong collection assets, tái sử dụng tức thì.
  5. Gọi mô hình: Chỉ gọi mô hình tạo ảnh khi chưa có trong kho lưu trữ.
  6. Sinh Thumbnail nhẹ: Tạo ảnh preview 256px cho client tải nhanh; ảnh gốc lưu StorageAdapter.
  7. Ghi nhận sở hữu: Lưu bản ghi vào generated_images gán với phiên người dùng.

⚙️ Quản Lý Tác Vụ Nền & Worker (Fail-Closed Queue)

Kiến trúc hàng đợi bền vững dựa trên MongoDB Lease Queue với cơ chế thẩm định hợp đồng chặt chẽ trước mọi thay đổi trạng thái.

🔄 Máy Trạng Thái (State Transitions)
[queued] ──(claim_next_job)──► [processing]
  │
  ├──(validate_job_result OK)────► [completed] (Bắt buộc có url)
  ├──(validate_retry_metadata)──► [queued] (Thử lại max 3 lần)
  ├──(validate_job_error)────────► [failed] (Lỗi đã khử khuẩn)
  └──(cancel_job)────────────────► [cancelled]
🛡️ Quy Tắc Thẩm Định Fail-Closed
  • Validate trước khi Mutate: Tuyệt đối không thay đổi RAM _jobs hay gọi MongoDB update nếu schema lỗi.
  • Worker Result bắt buộc: Task trả về None, {}, thiếu url, hoặc chứa trường lạ đều bị từ chối chuyển sang completed.
  • Khử khuẩn mã lỗi: Không lưu raw traceback hay secrets vào database; fallback về error canonical schema.
  • Khắc phục Job kẹt: Lease timeout 180s với heartbeat 30s. Nếu worker chết, lease tự động nhả.

🎯 1. Mục Tiêu & Phân Tách Hai Lớp (Two-Layer Separation)

Lớp Decision Engine hiện tại không sinh câu trả lời văn bản dài. Nó nhận state đã redaction và trả về quyết định có kiểu dữ liệu cố định để backend hỗ trợ phân loại intent và đánh giá evidence.

[1] LLM / Chatbot ➔ Sinh nội dung tư vấn tuyển sinh, giải thích thân thiện.
[2] JEV Decision Support ➔ Phân loại intent / evidence theo schema; timeout, confidence gate hoặc lỗi đều quay về pipeline cũ.
📐 2. Ba Nhóm Quyết Định Nội Bộ (Typed Decisions)
Binary Decision: allow / deny, valid / invalid, safe / unsafe, cache / no-cache.
{"type": "binary", "result": true, "confidence": 0.96}
Choice Decision: Chọn 1 nhãn enum xác định trước (admission, tuition, major, artifact, human_review).
{"type": "choice", "selected": "tuition", "confidence": 0.91}
Score Decision: Chấm điểm chuẩn hóa (risk score, quality score, source reliability).
{"type": "score", "score": 0.87, "level": "high", "confidence": 0.93}
* Tuyệt đối không trả về bất kỳ định dạng nào ngoài schema đã định nghĩa trước.

🔒 9. Chế Độ Riêng Tư & Định Hướng Tự Host
  • Off (mặc định): Không gọi JEV, không cần API key và không gửi state ra nhà cung cấp.
  • Shadow / Assist: Có gọi TypeSafe JEV; chỉ gửi state tối thiểu đã redaction, tối đa theo JEV_MAX_STATE_BYTES.
  • Tự host 100%: Là mục tiêu R&D tương lai, chưa phải trạng thái runtime hiện tại.
  • Không đưa Secret vào Model: Rào chắn Log Sanitization loại bỏ cookie, token và thông tin định danh trước khi ghi vết.
  • Auditability & Rollback: Mỗi quyết định đều kèm trace_id và có thể quay về Deterministic Rules bất kỳ lúc nào nếu model có dấu hiệu bất thường.
